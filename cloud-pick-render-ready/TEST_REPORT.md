## 실행 결과

- `node build.mjs` 성공.
- `npm test`: Node.js 22.16.0, 80개 통과, 실패 0. 전체 로그의 실행 시간 약 112초.
- 새 기록 단위 테스트 19개: R1/R2/R3/R10 표시 수, 시간순·최근 2회 제한, 본인/로비/준비/결과 화면 제외, 과거 보드 값 사용, 충돌·미선택 구분, 중복/재접속/새 경기 초기화, 현재·미래 기록 제외, 원본 상태 불변, 기존 선택 비공개, 빌드 순서.
- 기존 HTTP/SSE 테스트 재실행: 실제 로컬 클라이언트 4개로 랜덤 매칭 10라운드, 비공개 선택, 정확한 득점, 점수 동기화, 재접속, 재매칭, 취소, 2인+봇 보충과 친구 방 회귀를 확인했습니다.
- 기존 10,000개 seed 보상곡선 및 타이머 회귀, 지정한 불투명 색상 쌍 8개의 대비 검사가 포함됩니다. 전체 사이트 WCAG 적합성 주장은 아닙니다.
- Chromium / Playwright 화면 검사 92개 통과, JavaScript 예외 0. 320·360·390·768·1024·1440px에서 R1/R2/R3 기록, 긴 닉네임, 당시 6코인·겹침, 미선택, 시간순 표시, 페이지 및 텍스트 가로 넘침, 현재 목적지 비공개를 확인했습니다.
- 브라우저 검사의 화면 사례는 실제 Room의 점수 규칙으로 만든 테스트 snapshot을 사용했습니다. 별도로 수정하지 않은 앱에서 봇 경기 두 라운드를 완료해 R3의 6개 상대 기록을 확인하고, 기존 4단계 튜토리얼을 끝까지 진행했습니다.

## 재현

```sh
node build.mjs
npm test
# 별도 Playwright + Chromium 환경에서만:
python tests/recent-history.browser.py
```

브라우저 실행 경로는 CHROMIUM_PATH, 결과 디렉터리는 QA_OUTPUT으로 지정할 수 있습니다. 테스트 snapshot 주입 함수는 테스트 중 메모리상의 HTML에만 추가되고, 실제 public/index.html에는 포함되지 않습니다. 게임 서버에 테스트용 API를 추가하지 않았습니다.

## 변경하지 않은 것

게임 보상·득점·시간·매칭 알고리즘은 그대로입니다. game.js의 변경은 버전 문자열뿐입니다. 서버가 이미 보내는 공개 history로 상대 최근 2회 원자료를 렌더링합니다. 전체 기록 버튼은 경기 종료 후에만 표시합니다. 기능과 무관한 슬로건·성격/확률 분석은 추가하지 않았습니다.

## 제한

실행 환경에서 외부 GitHub 호스트의 DNS 조회가 실패했고, Chromium의 URL 이동도 관리자 정책으로 차단되었습니다. 브라우저 검사는 로컬 HTML을 about:blank에 렌더링했으며, 통신 검사는 별도 Node 클라이언트로 수행했습니다. 정책을 우회하지 않았습니다. Render 배포 상태는 연결 도구로 별도 확인합니다.

공개 주소의 다중 브라우저 전체 경기, Safari/iOS 실기기, 실제 P95 경기시간, 사람의 패턴 예측 정확도·재미·밸런스는 이번 테스트로 입증하지 않습니다.
