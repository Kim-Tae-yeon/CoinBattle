# CoinBattle

**CLOUD PICK · AFTER DARK**는 구름 위의 코인을 두고 서로의 선택을 읽는 웹 멀티플레이 심리전 게임 프로토타입입니다. 가을밤의 차분한 색감과 종이 오리기풍 동물 캐릭터를 배경으로, **방 코드 없는 랜덤 매칭**, 친구끼리 플레이, 봇 연습을 지원합니다.

> 혼자 고른 구름의 코인은 전부 내 것. 같은 구름에 모이면 모두 빈손.

**게임 주소:** https://cloud-pick-after-dark-ux.onrender.com

아래 설명과 실행 방법은 실제 배포 경로인 `cloud-pick-render-ready/` 소스를 기준으로 합니다. `cloud-pick-ux/`와 기존 ZIP은 이전 버전 보관본입니다.

## 프로젝트 목표

CoinBattle은 **간단한 선택 하나로 경쟁의 긴장감을 만드는 파티 게임**을 목표로 합니다. 더 많은 코인이 있는 구름을 노릴지, 다른 사람이 고르지 않을 구름으로 피할지 판단하는 과정이 핵심입니다. 모두의 선택이 동시에 공개되는 순간, 그 판단의 결과를 확인할 수 있습니다.

복잡한 조작보다 **상대의 선택을 예측하는 재미**에 집중합니다. 처음 접하는 플레이어도 직접 해보며 규칙을 익힐 수 있도록 체험형 튜토리얼을 제공하고, 각 화면에는 그 단계에서 필요한 정보와 행동을 우선 배치합니다. 가을밤의 차분한 분위기와 짧은 선택 시간의 긴장감이 공존하는 경험을 지향합니다.

## 랜덤 매칭으로 시작

게임 주소에서 **랜덤 매칭 → 이름 입력 → 상대 찾기**를 선택합니다. 이름을 비워도 시작할 수 있고, 매칭되면 별도 방장 조작 없이 자동으로 출발합니다.

| 같은 서버의 대기자 | 경기 시작 방식 |
|---|---|
| 사람 4명 | 접속 확인 후 즉시 시작 |
| 사람 2~3명 | 첫 대기자 기준 20초 후 빈자리를 봇으로 채워 시작 |
| 사람 1명 | 다른 사람이 올 때까지 대기; 혼자 몰래 봇 경기로 전환하지 않음 |

랜덤 매칭은 **5라운드 / 선택 시간 10초**로 통일합니다. 봇은 준비 화면과 경기에서 구분해 표시합니다. 대기 숫자는 실제 해당 묶음의 인원이며 예상 대기 시간이나 전체 온라인 인원이 아닙니다. 대기자는 참가 순서로 묶고 좌석은 무작위로 배정합니다. 실력·랭크·지역 기반 매칭은 아닙니다.

대기 중 취소와 새로고침 복구를 지원합니다. 경기가 끝나면 누구나 **다시 매칭**으로 새 상대를 찾을 수 있습니다. 접속자가 적으면 이전 상대를 다시 만날 수 있습니다. 기존 친구 방과 봇 연습은 **다른 방식으로 플레이**를 펼치면 선택할 수 있습니다.

## 게임 규칙

3×3 구름 보드에서 각 플레이어는 자기 옆의 구름 3개 중 하나를 비밀리에 선택합니다. 가운데 구름에는 3코인, 네 모서리에는 라운드마다 위치가 바뀌는 1·1·2·2코인이 놓입니다.

- **혼자 선택한 구름:** 표시된 코인을 획득합니다.
- **두 명 이상 선택한 구름:** 해당 구름을 고른 사람 모두 이번 라운드에 0코인을 얻습니다. 이미 모은 코인은 잃지 않습니다.
- **선택과 확정:** 확정 전에는 목적지를 바꿀 수 있습니다. 모두 확정하거나 시간이 끝나면 동시에 공개합니다. 시간 종료 시 마지막 선택이 적용되고, 한 번도 고르지 않았다면 0코인입니다.

마지막에 누적 코인이 가장 많은 플레이어가 승리하며 동점이면 공동 우승입니다.

## UX와 조작

처음 화면, 시작 준비, 매칭 대기, 플레이, 결과를 나누고 상세 규칙과 설정은 필요할 때 열도록 구성했습니다. **4단계 체험형 튜토리얼**은 코인 획득 → 겹침 → 선택 변경과 확정 → 제한 시간 순서로 진행하며, 처음 세 단계에는 시간제한이 없습니다.

구름 클릭·터치 또는 숫자 `1`·`2`·`3`으로 선택하고 `Enter` 또는 **선택 확정** 버튼으로 확정합니다. 소리와 움직임 줄이기 옵션을 제공합니다. 어두운 배경과 글자·버튼의 명도 차이를 높였으며, 선택 상태는 밝은 면과 체크 표시로 함께 구분합니다.

봇 연습과 튜토리얼은 메뉴를 열면 일시정지합니다. 온라인 경기와 매칭은 메뉴를 열어도 계속 진행합니다.

## 로컬 실행 및 테스트

**Node.js 22 이상**에서 저장소 루트 기준으로 실행합니다. 별도 npm 패키지는 필요하지 않습니다.

```sh
cd cloud-pick-render-ready
node build.mjs
npm test
node server.mjs
```

브라우저에서 `http://localhost:3000`에 접속합니다. 빌드된 `public/index.html`을 직접 열면 튜토리얼과 봇 연습을 할 수 있지만, **HTML 단독 실행은 랜덤 매칭 서버를 대신하지 않습니다.** 다른 사람도 같은 Node 서버 주소에 접속해야 합니다. 다른 기기에는 `localhost`가 아닌 서버의 네트워크 주소를 알려주세요.

## 기술 구성 및 배포

프런트엔드는 HTML·CSS·JavaScript와 Canvas 2D, 백엔드는 Node.js입니다. 대기열은 HTTP로 상태를 확인하고, 경기 입력은 HTTP 요청으로 전달하며, 경기 동기화는 SSE(Server-Sent Events)로 처리합니다. 다른 사람의 목적지는 결과 공개 전까지 전달되지 않습니다.

```text
cloud-pick-render-ready/
├─ server.mjs           # HTTP API, SSE, 공개 매칭과 친구 방
├─ build.mjs            # 소스를 단일 HTML로 빌드
├─ package.json
├─ tests/               # 대기열·4인 통신·명도 대비 테스트
└─ src/
   ├─ game.js           # 공통 게임 규칙
   ├─ matchmaker.mjs    # 대기·준비·취소·만료 처리
   ├─ match-ui.js       # 매칭 화면과 연결 복구
   ├─ ui.js             # 화면 흐름, 튜토리얼, 입력
   ├─ art.js            # Canvas 보드와 캐릭터
   ├─ styles.css        # 기본 UI
   ├─ match-styles.css  # 대기 화면
   ├─ contrast.css      # 명도 대비와 선택 상태
   └─ template.html     # 화면 구조
```

`public/index.html`과 `src/app.js`는 빌드로 생성됩니다. 수정할 때는 원본 모듈을 편집하고 다시 빌드하세요. 랜덤 매칭은 서버 변경도 필요하므로 HTML만 교체하면 적용되지 않습니다.

기존 Render 서비스는 `main`의 변경을 자동 배포하며 다음 명령을 사용합니다.

```text
Build: cd cloud-pick-render-ready && node build.mjs
Start: cd cloud-pick-render-ready && node server.mjs
상태 확인: /api/health
```

상태 응답의 `version`, `revision`, `matchmaking.enabled`로 적용 버전을 확인할 수 있습니다. 기본 매칭 대기는 20,000ms이며 `MATCH_FALLBACK_MS` 환경 변수로 조정합니다.

## 프로토타입 범위

방·대기열·점수는 단일 서버 프로세스의 메모리에 저장되므로 서버가 재시작되면 사라집니다. 여러 인스턴스가 대기열을 공유하지 않으므로 **한 인스턴스**로 운영해야 합니다. 계정·영구 전적·신고 및 제재·실력 기반 매칭·대규모 분산은 포함하지 않습니다.

검증 범위는 [테스트 보고서](cloud-pick-render-ready/TEST_REPORT.md), 추가 실행 안내는 [프로젝트 README](cloud-pick-render-ready/README.md), 초기 UX 설계는 [튜토리얼 문서](cloud-pick-ux/UX_TUTORIAL.md)를 참고하세요.
